# 23 排版版：每一行都带缩进（缩进不再是段落信号）

- **现象**：文件来自下载站的精校版——全篇**每一行**都带缩进（续行也缩进），
  而且**行与行之间还留一个空行**（双倍行距）。段落被硬换行切成一段多行。
  旧判据下这种文件**一行都合不上**（实测一本 2348 非空行的排版版，合并 0 次）：
  - `WhitespaceRules.hasLeadingWhitespace(next)` 先命中「有缩进 → 新段落」，直接否决；
  - 就算绕过它，`paragraphIndented` 那条路又要求 `blankLinesBetween == 0`，
    而这里每两行之间都夹着一个空行。
- **期望**：段落按语义合回——上一行没说完就并，空行不当边界；缩进行里的**完整句子**仍然
  各自成段。
- **档位**：STANDARD。
- **关键判据**：`ParagraphRules.shouldMerge` 的第一条路。下一行带缩进时不再一票否决，
  改为看**上一行有没有说完话**（行尾是不是句末标点）：
  - 收尾了 → 缩进照旧按「新段落」算（正常书的行为一个字节都不变，因为有这个安全边界）；
  - 没说完 + 引号未闭合，或没说完 + 行长达 `WRAP_MIN_CHARS`（16 字）→ 判定为硬换行续行，并回。
  - 没说完、但**下一行以引号起头** → 那是新对话，另起一段（见用例里的第四段）。
    网文里「上一段结尾漏个标点」很常见，少了这条守卫，后面整段对话会被吞进上一句里——
    这在真实文件上实测到了。
  空行在这条路里不作数（它只是行距），但幂等仍然成立：合并产物的行尾必然是句末标点，
  第二次跑时走「收尾」分支。
- **来源**：真实文件实跑暴露。这类「每行缩进 + 行间空行」的排版在下载站精校版里很常见，
  是当前语料（缩进分段 / 顶格一段一行）没覆盖的第三种形态。
