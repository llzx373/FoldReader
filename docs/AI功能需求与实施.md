# FoldReader AI 功能需求与实施文档

**版本**：v1.4（草案，待评审）
**政策依据**：`docs/需求与设计说明书.md` 附录 v2.6（网络策略修订：AI 与 WebDAV 例外）
**参考实现**：[manga-translator-android](https://github.com/jedzqer/manga-translator-android/)（漫画翻译线）

## 1. 总则

### 1.1 核心模式

FoldReader 的 AI 功能统一遵循一个形态：

> **AI 产出规则 / 配置 / 元数据 / 旁挂副本 → 用户预览确认 → 本地确定性执行。**

- AI 不进入任何运行期路径：阅读、分页、清洗、搜索的执行逻辑与今天完全一致；
- 每个 AI 产出都可预览、可推翻、可删除，推翻后系统行为逐字节回到现状；
- 沿用「宁可漏不可错」的确定性哲学（v2.2 系列匹配、SAF 降级的同一口径）；
- 正文外发逐次明示，成本按用户主动动作结算；
- **提示词透明**：内置系统提示词全文可在设置页查看，按页翻译支持当次临时修改（见 2.5）。

### 1.2 范围

| 做 | 不做 / 移出 |
| --- | --- |
| 功能优化类 AI：章节规则生成、清洗配方推荐、元数据补全 | 前文回顾、选中即问、全书问答、人物关系图谱（内容理解类，无限期后置） |
| 文本翻译：选段 / 按页 / 单章(块) / 全书（TXT/EPUB/FB2/PDF 文本模式），三种对照视角 | WebDAV 备份（v2.6 已留政策位置，本规划不含） |
| 漫画翻译：本地 OCR + LLM 翻译 + 气泡覆盖层，按页/批量两种模式，三种对照视角 | 漫画 / 扫描件 OCR 以外的图像处理（inpainting 修复、画质增强） |
| 扫描版 PDF 文本层（OCR 引擎的第二个消费者） | 端侧 LLM 推理（llama.cpp 等，体积与设备覆盖面过不了依赖门槛） |
| 非 AI 前置：TTS 听书、人物出场索引 | 在线书城、社交、账号体系（产品底线，不变） |

### 1.3 决议（v1.4 已拍板）

| # | 问题 | 决议 |
| --- | --- | --- |
| R1 | 服务商协议 | **兼容三种**：OpenAI Chat Completions、OpenAI Responses、Anthropic Messages。`AiProvider` 三个实现，设置页预设按协议分组 |
| R2 | HTTP 与流式 | **做流式（SSE），引入 OkHttp**（主依赖）+ **MockWebServer**（test 依赖）。翻案理由：①传输层（分块/超时/取消/socket 回收）用成熟实现而非自维护；②MockWebServer 让三协议的 SSE 流可以在 JVM 单测中端到端锁定（粘包/断流/限流），网络层从"只能真机验证"变成"测试集锁定"；③为将来 WebDAV 预留同一网络栈。SSE 事件→文本增量的映射仍收敛在各 Provider 内（纯解析，单测） |
| R3 | 翻译模型 | 与通用模型分开配置（翻译对质量敏感，可单独选好模型） |
| R4 | 目标语言 | **支持多国语言**（首版：简体中文 / 繁体中文 / 英文 / 日文，列表可扩）；逐书可选，默认跟随系统语言为中文时简中 |
| R5 | 全书翻译中翻到未译章（块） | 支持插队单章（块）翻译 |
| R6 | 术语表 | **支持全局与单书两个层级**（漫画另有系列层级）：全局对所有书生效，单书只对本生效；优先级 书 > 系列 > 全局；首版 UI 只做确认/否决候选与全局表增删 |
| R7 | OCR 模型获取 | 不进 APK。**用户自行下载模型文件，应用提供导入入口**（SAF 选择文件 → 校验格式与哈希 → 落 `filesDir/models/`，可删除）；设置页给出模型清单与官方下载地址指引 |
| R8 | OCR 首版语言 | **日文 + 英文 + 中文**（rec 模型按语言独立导入；中文模型同时服务漫画与扫描版中文 PDF） |
| R9 | 气泡检测模型 | 首版引入（分块太碎会推高 LLM 成本、降低翻译质量） |
| R10 | 条漫跨页气泡合并 | M23，首版按页独立翻译为已知瑕疵 |
| R11 | 按页翻译 | **电子书与漫画通用**：阅读中可对当前页单独即时翻译（流式渲染）；发起前可**临时修改当次提示词**（仅当次生效，不改内置模板），作为翻译质量调优的主路径 |
| R12 | 无章节/超大文件 | **逐段切块翻译**：整本无章节（或单章超过阈值，约 4000 字）时，按段落边界切成「块」（2000–4000 字/块）；块是翻译、进度与对齐的最小单位，译本 `.toc` 生成对应的伪目录 |

## 2. 技术底座（M14，一切 AI 功能的前置）

### 2.1 模块结构

新增 `core/ai/`，保持纯逻辑可测（参照 `clean/` 整包纯 JVM 的约束，prompt 构造与结果解析不引用 `android.*`，Android 依赖收在 `core/ai/android/`）：

```
core/ai/
├── AiProvider.kt              # 接口：chat(messages): Flow<String>（SSE 流式，R2）
├── openai/ChatCompletionsProvider.kt   # OpenAI Chat Completions（R1）
├── openai/ResponsesProvider.kt         # OpenAI Responses（R1）
├── anthropic/AnthropicProvider.kt      # Anthropic Messages（R1）
├── prompt/                    # 各功能的系统提示词模板与响应解析（纯 JVM，单测覆盖）
├── gate/AiContentGate.kt      # 外发确认与记录（见 2.3）
└── android/
    ├── CredentialStore.kt     # Keystore 加密的 key 存取
    └── ModelManager.kt        # OCR 模型导入/校验/删除（M21 用）
```

三个协议实现共用：OkHttp 传输（单例 `OkHttpClient`，超时/连接池统一策略）、错误模型（超时/限流/额度/网络不可达 → 可读文案）；差异只在请求体构造与 SSE 事件→文本增量映射（各 Provider 内，纯解析）。**测试用 MockWebServer 端到端锁定**：三协议的 SSE 流（正常增量/粘包/中途断流/限流 429/非 200 错误体）各配 JVM 用例，不依赖真机与外网。

**装配**：`AppContainer` 中按配置存在与否惰性创建 `AiProvider` 与 `OkHttpClient`——未配置 key 时不存在任何网络组件，OkHttp 不创建任何连接（v2.6 约束 1）。网络代码不出现在阅读、导入、书架主路径上。

### 2.2 设置页「AI 服务」

- 总开关（默认关）→ 展开：**协议预设**（OpenAI Chat / OpenAI Responses / Anthropic，R1）+ 服务商地址预设（DeepSeek / OpenAI / Anthropic / 通义 / 自定义）+ base URL + **通用模型** + **翻译模型**（R3）+ API key + 「测试连接」；
- **默认目标语言**（R4）：简中/繁中/英文/日文，逐书可在翻译发起时另选；
- 未配置完成时，全书所有 AI 入口**不显示**（界面零变化，不是置灰）；
- **「内置提示词」**：按功能（章节规则 / 清洗配方 / 元数据 / 文本翻译 / 漫画翻译）**只读查看**应用内置系统提示词全文——发给模型的规则对用户完全透明；
- 「外发历史」（每次外发：时间、书籍、数据范围、估算 token）；
- 「清除全部 AI 数据」（译本/术语表/OCR 缓存/覆盖层，不含 key——key 单独「清除凭据」）。

### 2.3 凭据与外发合规（v2.6 约束 2、3、5）

- API key 存 Android Keystore 加密的私有存储；不进备份导出、不写诊断日志、不出现在崩溃报告与 `dumpsys`（沿用 PDF 密码规则）；
- 任何正文/采样/图像外发前，界面明示去向（服务商、数据范围）；首次启用每类功能时一次性确认，外发历史可随时审计；
- Manifest 增加 `INTERNET` 与 README / 应用内隐私说明改写**同一提交**。

### 2.4 依赖评估（M5.12 门槛）

| 依赖 | 体积（R8 后） | 用途 | 结论 |
| --- | --- | --- | --- |
| OkHttp（+okio） | ~1MB | HTTP 传输与 SSE 流式 | **引入（M14，R2 已拍板）**；为将来 WebDAV 预留同一网络栈 |
| MockWebServer | test 依赖，不进 APK | 三协议 SSE 端到端单测 | **引入（M14，R2）** |
| kotlinx.serialization | ~1MB | 请求/响应 JSON | 引入（M14） |
| onnxruntime-mobile | ~10MB | OCR 推理 | 引入（M21） |
| OCR 模型（det/rec/气泡检测） | ~40MB | 文字检测识别 | **不作依赖**，用户自行下载后导入（R7） |

依赖纪律：OkHttp 的引入是逐案评审的结果，不构成放宽 M5.12 门槛的先例；后续新依赖仍按"体积、维护成本与收益写进方案"的标准逐案评估。

### 2.5 提示词管理

- 所有内置系统提示词集中在 `core/ai/prompt/`，按功能分文件（纯 JVM，响应解析随单测锁定输出契约）；
- 设置页「内置提示词」只读查看全文（2.2）；
- **临时覆盖**：按页翻译（电子书 5.2 / 漫画 6.2，R11）发起前可当次修改提示词，仅当次生效、不写回内置模板——换说法立刻重译一页看效果，是调优主路径；
- 提示词变更视为行为变更：进 CHANGELOG；涉及输出格式的，同步更新解析单测。

## 3. 阶段 0：非 AI 前置（与 AI 线并行，随时可开工）

### 3.1 M13：TTS 听书

- 系统 `TextToSpeech` API，离线、免费、无模型；
- 「从当前位置朗读」/「朗读本章」；与自动翻页联动（读完一页翻一页）；
- MediaSession 支持耳机按键与锁屏控制；
- 验收：折叠/展开切换朗读不中断；进度条与朗读位置同步。

### 3.2 人物出场索引（建议并入 M13 或紧随）

- 纯规则：高频 2-4 字专名候选 + 称谓词过滤，统计首次出场章节；
- 目录面板加「人物」页签，点击跳转；
- **下游价值**：是文本翻译术语表（5.3）与漫画译名表（6.2）的初始数据来源。

## 4. 功能线 A：功能优化类 AI

### 4.1 M15：AI 章节规则生成

**痛点**：无规律 TXT（合集、翻译体）章节识别失败后退化为纯进度跳转，是死路；手写正则门槛过高。

**流程**：

1. 入口：目录面板「未识别到章节」状态与书籍详情页，显示「AI 识别章节」；
2. 本地用现有章节扫描器粗筛「疑似标题行」候选集（几百行，非全书）；
3. 发给模型，返回 1~3 条候选正则 + 每条的设计说明；
4. 逐条在本地跑真实切分，预览：章节数、前 20 个标题、异常标记（超长章 / 空章 / 首章前有大段孤儿文本）；
5. 用户选一个 → 存为该书的**自定义章节规则**（复用现有数据结构与设置页规则库），重扫目录。

**落点**：零新数据模型；最坏结果是用户不选，无副作用。
**prompt 约束**：要求模型只输出正则与说明，解析失败即丢弃该候选（纯 JVM 解析，单测覆盖畸形响应）。
**验收**：拿 3~5 本规则库失败的 TXT，AI 正则可切出可用目录；预览→确认→重扫全流程通。

### 4.2 M16：AI 清洗配方推荐

**痛点**：三档预设 + 14 开关 + 自定义广告正则，普通用户不知道开哪个。

**流程**：

1. 入口：「智能整理」对话框加「AI 推荐配方」；
2. 采样全书若干段脏文本（含头尾，广告高发区）发给模型；
3. 返回：建议启用的开关列表（直接映射 `CleanToggles.ENTRIES`）+ 0~3 条针对该书广告/水印的自定义正则 + 「这本书的问题是什么」一段说明；
4. 产出一份 `CleanProfile`，之后完全走现有管线：清洗预览报告 → 确认 → 物化。

**红线**：AI 不进清洗执行路径。v2.3 的幂等性、测试集、确定性一个都不受影响——验收时全语料测试集必须全绿。

### 4.3 M17：元数据补全 + 智能分组

**流程**：导入后（或书架批量触发，带进度与取消）采样书籍开头几 KB → 返回结构化书名 / 作者 / 一句话简介 / 题材标签（固定枚举：玄幻、都市、历史、科幻…）。

**落点**：

- `books` 表加 `author` / `synopsis` / `genreTag` / `metaSource`（AI/user/import）四列（一次 DB 迁移）；
- AI 填的值在详情页标「AI 生成」；用户可编辑覆盖，`metaSource=user` 后不再被 AI 改写；
- 题材标签喂给规则版「按题材自动分组」；封面生成可带题材配色。

## 5. 功能线 B：文本翻译

### 5.0 总体架构：译本即副本

复用两个现成先例拼出形态：

- **清洗副本**（v2.3）：`filesDir/` 下物化副本，阅读器透明读取；
- **PDF 双模式**（v2.1）：两种模式各自记位置、互不换算、切回各停各的（`keepPagedAnchor` / `keepTextAnchor` 对称结构）。

```
一本书
├── 原文（不动一个字节）
└── 译本 filesDir/translations/<bookId>/<lang>/content.txt + .toc
      阅读菜单「原文 / 译文」切换
      两种模式各自记进度、书签、标注，互不换算
```

四个架构红利：

1. **锚点零侵入**：译文有自己的字符偏移，不需要"原文第 N 字 ↔ 译文第几字"这种不可能的对齐；
2. **排版零成本**：译本就是 TXT，走同一条分页管线，双页/仿真翻页/主题自动可用；
3. **成本可控**：按翻译单位增量物化，译一个存一个，中断可续，单位可重译；
4. **格式全覆盖**：所有文本格式导入时已压平为 TXT + `.toc`，翻译的是压平产物，EPUB/PDF 零特殊代码。

**翻译单位与对齐单位 = 章或块**（R12）：

- 有章节的书：单位 = 章，译本 `.toc` 与原文共用章节边界（翻译不跨章）；
- **整本无章节，或单章超过阈值（约 4000 字）**：按段落边界切成「块」（2000–4000 字/块），块即翻译、进度与对齐单位；译本 `.toc` 生成对应的伪目录（「第 1 节 / 第 2 节…」），目录面板可正常跳转；
- 单章切块时块边界不跨段（段落是块的内部结构，块不切段落）；
- 模式切换按「单位号 + 单位内进度比例」定位（与「智能整理」换内容时同一口径），首次切换一句话告知。

**翻译粒度序列**（从小到大，全部用户主动触发）：**选段（5.1）→ 按页（5.2）→ 单章/块（5.2）→ 全书（5.3）**。

### 5.1 M18：选中即译

- 长按选字动作条加「翻译」（v2.2 既定合规入口）；
- 底部卡片**流式**显示译文（R2）；源语言自动检测，目标语言默认按设置页（R4），卡片上可临时换；
- 可选「存为批注」锚定当前偏移；
- 价值：零新存储结构，验证底座在真实阅读路径上的表现。

### 5.2 M19：按页翻译 + 单章（块）翻译 + 视角 1（原/译切换）

**按页翻译**（R11，与漫画 6.2 同一能力）：

- 阅读菜单「翻译本页」：把当前页（双页模式下当前跨页两页）的正文即时翻译；
- 发起前弹出确认页：显示预估 token、可**临时修改当次提示词**（仅当次生效，见 2.5）——换说法立刻重译一页看效果，是翻译质量调优的主路径；
- 结果以**对照面板流式**展示：原文段下接译文段、背景色稍深（视角 3 的同款样式），边生成边显示；
- **不落译本副本**——按页翻译是即时查看与调优手段，需要沉淀时用「翻译本章」。

**单章（块）翻译**：

- 阅读菜单「翻译本章」（无章节书显示「翻译本节」，R12）；目录面板每章/块状态：未译 / 翻译中 / 已译；
- 后台协程翻译，不阻塞阅读；译完该单位即可切换；
- 单章（块）可重译（换模型 / 改目标语言 / 不满意），重译只作废该单位；
- 翻译结果按**段落结构化**落盘（prompt 要求模型按段落数组返回，解析校验失败即该单位重试），供段落对照视角（5.4）直接使用——不做事后对齐；
- 全书翻译进行中翻到未译单位：支持插队（R5）。

### 5.3 M20：全书批量翻译 + 术语表 + 视角 2/3

- 入口：书籍详情页「翻译全书」→ 确认页显示**目标语言**（R4，默认设置页值）与**预估成本**（字符数 → token 估算 → 金额），逐书确认；
- 批量队列复用 `BookPrewarmQueue` 模式：串行、让出、失败重试、断点续译、进度可见可暂停可取消；长时间任务前台服务 + 完成通知；
- **术语表（Glossary）**——跨章一致性的关键（R6）：
  - `glossary_terms(scope[global|series|book], ownerKey, source, target, origin[auto/user], confirmed)`；
  - **全局表**对所有书生效；**单书表**只对本书；漫画另有**系列表**（6.2）；注入优先级 书 > 系列 > 全局，同 source 高层级覆盖低层级；
  - 初始来源：人物出场索引（3.2）+ 前 3 章（块）翻译后模型回填候选；
  - 每个翻译单位调用时按优先级合并注入 prompt；
  - 首版 UI 只做确认/否决候选与全局表的增删；
  - 术语表（各层级）进备份；译本不进（可重译）。

### 5.4 翻译三视角（文本）

打开翻译后，阅读器提供三种视角（漫画版见 6.2）：

1. **切换视角**（M19）：菜单「原文 / 译文」切换整书正文模式，按「单位号 + 单位内进度比例」定位——对照查看翻译质量；
2. **双页对照**（M20）：展开双页模式下**左页原文、右页译文**——铰链即书脊的形态与对照阅读天然匹配。实现上左右各挂一个 Paginator（原文内容与译本内容各自分页，页宽取左右安全区较小值的既有规则不变），翻页按章/块对齐，允许两侧按比例漂移后在单位边界追上；内存开销双倍，仅双页布局可用，单页/悬停退回视角 1；
3. **段落对照**（M20）：滚动模式下一段原文下方紧跟其译文，译文块背景色稍深（随阅读主题派生，不新增配色项）。段对段映射来自 5.2 的段落结构化落盘，不需要运行时对齐。

## 6. 功能线 C：OCR 与漫画翻译

### 6.0 OCR 的定位：通用文本层引擎

OCR 不是漫画专属组件。`core/ocr/` 一次建设，两处消费：

1. **漫画翻译**：页位图 → 文字检测 + 识别 → 带坐标文本块；
2. **扫描版 PDF 文本层**：设计书 v2.1 预留的翻案路径「页位图 → 自托管离线 OCR → 带坐标的文本层」，解锁搜索 / 选字 / 后续翻译。

技术栈（跟随参考项目验证过的组合）：**onnxruntime-mobile + PaddleOCR det/rec（ONNX）+ YOLO-seg 气泡检测（R9）**。纯离线、不依赖 GMS。模型由用户自行下载、应用内导入（R7），首版**日文 + 英文 + 中文**（R8）。

### 6.1 M21：OCR 引擎 + 扫描 PDF 文本层

- `core/ocr/`：ONNX 会话管理、det → rec 推理管线、结果（文本 + 归一化坐标）输出；
- `ModelManager`：模型清单（文件名 + 期望 SHA-256 + 用途 + 官方下载地址，含日/英/中三个 rec 模型）、**SAF 导入**（用户自行下载的模型文件 → 校验格式与哈希 → 落 `filesDir/models/`）、可删除；模型未就绪时相关功能入口优雅隐藏；
- **先落扫描 PDF**：页位图（`PdfPagedSource` 已有）→ OCR → 文本层，解锁全文搜索与拖框选字（选字坐标与 v2.2 页内锚点同一归一化体系）；
- 验收：中/英扫描 PDF 可搜索、可选字复制；模型导入/校验/删除全流程，错误文件明确报错；未导入时无残留入口。

### 6.2 M22：漫画翻译 v1

**页级管线**：

```
页位图（PagedImageSource 出图，已有）
 → [本地] 气泡检测（YOLO-seg）归并 + 文字检测（det）+ 识别（rec）→ 带坐标文本块
      OCR 结果缓存 filesDir/comic_translate/<bookId>/<pageIndex>.ocr.json
 → [云端] LLM 流式翻译（注入合并后的术语表 + 同页气泡上下文）
 → 覆盖层数据 filesDir/comic_translate/<bookId>/<pageIndex>.json
```

OCR 缓存与翻译结果分文件（参考项目做法）：换模型/改提示词重译不必重跑 OCR。

**翻译模式**：

- **按页翻译**（R11，与电子书 5.2 同一能力）：阅读菜单「翻译本页」即时翻译当前页，不等批量队列。发起前弹出确认页：显示预估 token、可**临时修改当次提示词**（仅当次生效，见 2.5）；气泡译文**逐个流式**出现；调好后可直接用同一提示词发起整卷批量；
- **批量翻译**：后台队列 + 前台服务 + 完成通知；逐页状态（未译/翻译中/已译/失败可重试）；断点续译。

**阅读侧**：

- `ComicPageView` 加 `TranslationOverlay` 层：气泡用**归一化（0..1）页内坐标**存储——与 v2.2 页内锚点同一坐标系，缩放 / 适配模式 / 双页 / RTL / 条漫滚动全部自动跟随，零坐标换算代码；
- 气泡底色采样周边背景色覆盖原文（不做 inpainting）；译文横排（不还原日文竖排，业界通行）；
- 气泡字体复用已有的字体导入机制。

**漫画翻译三视角**（与 5.4 文本视角对应）：

1. **切换视角**：菜单「显示译文」开关控制覆盖层显隐——同一页上切原文/译文，对照查看翻译质量；
2. **双页对照**：双页模式下**左页渲染原始页图、右页渲染同页 + 覆盖层**；两侧同页序号同步翻页——页式格式天然页对页，无对齐问题；
3. **气泡对照**：底部对照面板按阅读序列出本页全部气泡的「原文 / 译文」对，译文区背景色稍作区别（随主题派生）；气泡空间紧张，不做气泡内双行，对照以面板为准，点面板条目高亮对应气泡。

**术语表按系列共享**（R6）：`ComicSeriesMatch` 的主干归一化产出 `seriesKey`，同系列各卷共享一张术语表——译第 3 卷累积的译名第 4 卷自动继承。与全局/单书术语表同表（`scope=series`），注入时按 书 > 系列 > 全局 合并。

### 6.3 M23：漫画翻译 v2（视 v1 反馈定）

- 条漫 / 长图跨页气泡合并（R10）；
- 气泡位置手动微调（参考项目能力）；
- 可选「视觉模型 OCR」模式：整页图发多模态 LLM 一次完成识别+翻译——零本地模型，但每页成本高、坐标可靠性略差、**页图像外发**需逐书单独明示。

## 10. 风险与开放问题

| 风险 | 说明 | 对策 |
| --- | --- | --- |
| 三协议流式格式差异 | OpenAI Chat / Responses / Anthropic 的 SSE 事件结构互不相同，且各家可能调整 | 事件→文本增量的映射收敛在各 Provider 内；MockWebServer 锁定当前格式，协议变更时测试先红、只动一个文件 |
| OkHttp 版本维护 | 首个网络依赖，需跟踪安全公告 | 升级走常规回归（MockWebServer 用例 + 真机冒烟）；`proguard-rules.pro` 按其 consumer rules 校验 |
| 模型获取门槛 | 用户需自行下载模型文件（GitHub/HuggingFace 可达性不一，文件较大） | 设置页给官方地址与镜像指引；导入时校验格式与哈希，错误文件明确报错；模型清单版本化 |
| OCR 质量参差 | 手写体、艺术字、低分辨率扫描识别率低 | 识别置信度落库，低置信气泡在覆盖层标记；允许整页重识别；按页重译+临时提示词兜底 |
| 翻译成本失控 | 用户批量翻译多本大书 | 成本预估 + 外发历史 token 累计展示 + 队列可暂停 |
| 厂商对 ONNX 的兼容性 | 部分设备的 NNAPI 后端不稳 | 首版只用 CPU 后端；GPU/NNAPI 列为优化项 |
| 术语表质量 | 人物索引误识别污染术语表 | 候选需用户确认才生效（R6）；可按来源/层级筛选清除 |
| 切块对齐漂移 | 无章节书的「块」在原文改动（智能整理重洗）后边界失效 | 块的定义是确定性的（段落边界 + 阈值），重洗后重切块、译本按单位作废重建（同智能整理的显式作废链路） |
| 译本与原文单位错位 | 极端情况：原文单位边界在译本中语义不通 | 翻译不跨单位是硬约束；单位重译兜底 |
| 双页对照内存 | 文本视角 2 双 Paginator、漫画视角 2 双份页图，内存双倍 | 仅双页布局启用；`onTrimMemory` 时优先回收对照侧缓存 |
