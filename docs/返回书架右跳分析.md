# 「从阅读页返回书架，封面与右上/右下按钮整体向右跳」根因分析

> 复现环境：阔折叠内屏横屏（宽 ≥ 840dp、高 ≥ 480dp → 外壳为 `NavigationRail` 侧边导航）
> 实测设备：Xiaomi 2608BPX34C（Android 17 / API 37）内屏横屏 860×608dp（2364×1672px @440dpi）
> 结论（两个成因，第二个是真机实测的最终根因）：
> 1. 外壳 rail 宽度 = 80dp + start 侧 `systemBars∪displayCutout` inset，返回时该 inset 可能晚于书架首帧落地；
> 2. **挖孔（`displayCutout`）在沉浸期间会上报侧边 inset（140px = 50.9dp），`show(systemBars)` 之后
>    仍停留约 500ms 才消失**。只看 `systemBars` 的门控会提前放行 → 书架首帧带右侧 140px inset
>    （content 2004）、500ms 后该 inset 消失（content 2144）→ 左边缘不动、右边缘外扩 →
>    "封面与右上/右下按钮整体向右跳"。

---

## 0. 真机实测序列（Xiaomi 2608BPX34C，Android 17）

```
# 沉浸期间
reader immersive: reference=… systemBars=(0,0,0,0) cutout=(0,0,140,0)     ← 挖孔侧边 inset 只在沉浸期上报
# 返回
leaveReader: bars shown expected=(left=0, top=140, right=0, bottom=0)     ← 旧门控只看 systemBars
+2183ms leaveReader: gate passed after 5 frames, navigate                 ← 提前放行
+2261ms bookshelf: innerPadding=(0, 202.9dp, 50.9dp, 0) content size=2004 x 1114   ← 首帧带 140px 右 inset
+2687ms bookshelf: innerPadding=(0, 202.9dp,  0.0dp, 0) content size=2144 x 1114   ← 500ms 后消失 → 右跳 140px
```

（宽度 2004 → 2144 恰好等于 140px；`content pos` 的 x 不变，证明是右边缘外扩而非整体平移。）

### 0.1 第二次真机实测：inset 是"系统栏每次显隐后平台补报的瞬时值"

装上第一版修复（门控比对外壳 inset 全集）后复测，**仍然右跳一次**，日志给出了更精确的时序：

```
15:26:54.669 reader enter:      systemBars=(0,140,0,0) cutout=(0,0,0,0)     ← 进书时没有挖孔 inset
15:26:55.229 reader immersive:  systemBars=(0,140,0,0) cutout=(0,0,0,0)     ← 沉浸前一刻也没有
15:26:55.246 bookshelf: content size=2004 （innerPadding 右 50.9dp）        ← hide() 之后 17ms 才出现
...
15:26:56.664 leaveReader: 探测 systemBars=(0,0,0,0) cutout=(0,0,0,0)        ← show() 时也还没有
15:26:56.683 gate passed after 3 frames（3 帧全程 cutout=0）→ navigate
15:26:56.738 bookshelf: innerPadding 右 50.9dp, content size=2004           ← 导航后 55ms 才出现
15:26:57.199 bookshelf: innerPadding 右 0      content size=2144            ← 再 515ms 后消失 → 右跳
```

结论：**平台在每次系统栏显隐（`hide`/`show`）之后都会补报一次挖孔侧边 inset（140px），
约 500ms 后自行消失**。它出现得比门控的采样更晚，所以"等 inset 到位再导航"堵不住：
门控采样时该 inset 还没出现（比对通过），书架首帧却在它出现之后布局。

因此修复改为**在外壳根节点消费掉"超出参考快照的额外 inset"**（见第 4 节 `ExtraOverReferenceInsets`）：
书架首帧即按参考态（无瞬时 inset）布局 → content 2144，500ms 后瞬时值消失时布局不变 → 不再跳。

## 1. 现象与几何

书架内容区（封面网格、右上动作按钮、右下 FAB）位于 `NavigationSuiteScaffold` 的 content 槽，
该槽的位置由 rail 宽度决定。material3-adaptive-navigation-suite 1.5.0-alpha28 源码
（`NavigationSuiteScaffoldLayout`）：

```kotlin
// 测量：content 的宽度约束减去 rail 宽度
contentPlaceable = measurables.fastFirst { it.layoutId == ContentLayoutIdTag }
    .measure(constraints.copy(
        minWidth = layoutWidth - (navigationPlaceable.width * animationProgress).toInt(),
        maxWidth = layoutWidth - (navigationPlaceable.width * animationProgress).toInt(),
    ))
// 摆放：content 放在 rail 右侧
contentPlaceable.placeRelative((navigationPlaceable.width * animationProgress).toInt(), 0)
```

而 `NavigationRail` 自身宽度含其 windowInsets：

```kotlin
// NavigationRailDefaults.windowInsets
WindowInsets.systemBarsForVisualComponents.only(WindowInsetsSides.Vertical + WindowInsetsSides.Start)
// material3 内部：systemBarsForVisualComponents = systemBars.union(displayCutout)
```

内容页各 `Scaffold` 的 `contentWindowInsets` 同样是 `systemBarsForVisualComponents`，因此
**外壳布局真正吃到的 inset 集合是 `systemBars ∪ displayCutout`**：

- start 侧 inset 变化 → rail 变宽 → 内容区整体右移（封面、右上动作、FAB 一起右移），
  网格列宽同步变化（`GridCells.Adaptive`）→ 视觉上"封面成片向右跳"；
- end（右）侧 inset 变化 → 内容区宽度变化，右边缘外扩/收缩，右上/右下按钮位移最明显；
- top 侧（状态栏）晚到则表现为内容整体下移（`LargeTopAppBar` 变高）。

## 2. 触发链

1. 阅读页沉浸：`SystemBarEffects` 用 `BEHAVIOR_SHOW_TRANSIENT_BARS_BY_SWIPE` + `hide(systemBars)`
   → `systemBars` 归零，**同时平台开始在挖孔所在的侧边上报 `displayCutout` inset**（真机 140px）；
2. 返回时 `show(systemBars)` 由系统异步派发：状态栏/导航栏 inset 先到，
   **`displayCutout` 的侧边 inset 约 500ms 后才清除**；
3. 若在 `displayCutout` 清除前就 pop 回书架：书架首帧按"带挖孔 inset"的宽度布局（2004）；
4. 该 inset 清除后内容区右边缘外扩 140px（2144）→ **封面与右上/右下按钮整体右跳**。

（旧实现的两个漏洞：只看 `systemBars` 时完全看不到 `displayCutout`；
只看 `getInsetsIgnoringVisibility(systemBars)` 时，平台返回的也是"沉浸中"那一份值，
因此同样会提前放行。）

## 4. 修复要点（已在代码中）

| 位置 | 约束 |
|---|---|
| `ReaderScreen.leaveReader` | 退出阅读页（返回键 / 顶栏返回 / 菜单返回 / 错误页返回）统一走此路径：先 `BEHAVIOR_DEFAULT + show(systemBars)`，再由 `BarsRestoreGate` 等**外壳 inset 快照（`systemBars ∪ displayCutout`）等于沉浸前实测快照**且连续两帧稳定才导航；800ms 超时兜底（日志 `gate TIMEOUT` 即仍有跳动风险） |
| `ShellInsets` | 定义"外壳 inset" = `systemBars ∪ displayCutout`（= material3 `systemBarsForVisualComponents`），并提供"沉浸前实测快照"参考值；进阅读页（`reader enter`）与沉浸前（`reader immersive`）各记一次 |
| `FoldReaderApp` + `ExtraOverReferenceInsets` | **离开阅读页后的 1.2s 窗口内，把"超出参考快照的额外 inset"在外壳根节点消费掉**——真机上平台会在系统栏每次显隐后补报 500ms 的挖孔侧边 inset（且出现得比门控采样晚），只靠门控堵不住。额外量归零后本机制自然失效（`max(0, 实时-参考)`），因此不需要精确掐时间；只在刚离开阅读页的窗口启用，避免长期误抑制合法的新 inset（旋转等） |
| `BarsRestoreGate` | 不可退化为"某一边非零即放行"或"快照稳定即放行"：`show()` 刚发出时全零也可能稳定数帧；也不可用 `getInsetsIgnoringVisibility` 当期望值（`displayCutout` 的值不受显隐影响，会拿到沉浸期那一份） |
| 导航组件显隐 | 只用 `layoutType` 切换，禁止用 `NavigationSuiteScaffoldState.snapTo` —— 其内部 `animateFloatAsState` 会逐帧挤压内容 |

## 5. 历史版本为何仍跳

- `037dc7b` 的旧门控只等**状态栏 top** 非零（`snapshotFlow { statusBars.getTop() > 0 }`，200ms 超时）：
  横屏下 top（状态栏）先到就放行，侧边导航栏的 left/right inset 随后才到 → 仍右跳。
- `BarsRestoreGate` 初版只看 `systemBars`：漏掉沉浸期才上报的 `displayCutout` 侧边 inset
  → 真机上仍在 500ms 后右跳一次（本文第 0 节即该版本的实测序列）。
- 修复若未重新编译安装（例如装着 `app/build/outputs/apk/release` 里的旧包），设备上仍是旧行为。

## 7. 残留问题（进书方向）已随本次重构消除

打开书籍时方向相反：此前 `layoutType` 切到 `None` 会让尚在退场的书架内容整体左移
（实测 192→72px）。现阅读页已移出外壳 content 槽（见第 8 节），外壳形态与路由无关，
进书时书架只做 `scaleOut(0.94)+fadeOut`，**不再重排**（`content size` 全程 2208×576 恒定）。

## 8. 结构性修复：阅读页全窗口覆盖层（ReaderOverlay）

```
SharedTransitionLayout
└─ Box(fillMaxSize)
   ├─ NavigationSuiteScaffold(layoutType = 顶层形态，恒定)   ← rail 宽度只随系统栏 inset 变
   │  └─ FoldReaderNavHost: bookshelf / settings（+ reader 空占位）
   └─ ReaderOverlay(AnimatedContent, 整窗)                  ← 阅读页实际画面
```

- 阅读页不再受 content 槽宽度约束：进书时它从第一帧就是整窗宽高，**不会先窄后宽重排**；
- 书架退场期间外壳槽位不变 → 不再左移；
- 退书时 rail 早已在覆盖层背后恢复到位，书架首帧即终局（配合 `BarsRestoreGate`）；
- 封面共享元素仍成立：书架与覆盖层同属一个 `SharedTransitionLayout`，
  覆盖层把 `AnimatedContentScope` 作为 `animatedVisibilityScope` 传给 `ReaderScreen`；
- 阅读页的 `ViewModel`/`rememberSaveable`/`Lifecycle` 由覆盖层按 NavHost 的方式提供
  `LocalViewModelStoreOwner/LocalLifecycleOwner/LocalSavedStateRegistryOwner = readerEntry`
  ——阅读时长仍在该 entry 弹栈（`onCleared`）时落库（实测 bookId=19：48166ms → 70351ms → 79526ms）。

### 8.1 必须遵守的 entry 生命周期约束（踩过的坑）

NavHost 只在**转场跑完**时调用 `onTransitionComplete(entry)` 才把 entry 置为 `DESTROYED`。
阅读页目的地在 NavHost 里只剩空占位，若其转场时长为 0（`EnterTransition.None`），entry 会在
pop 的下一帧就被销毁，而覆盖层还在组合退场内容 → 阅读页每帧都在读 `animatedVisibilityScope.transition`
而重组 → `viewModel()` 访问已销毁 entry 的 ViewModelStore：

```
java.lang.IllegalStateException: You cannot access the NavBackStackEntry's ViewModels
after the NavBackStackEntry is destroyed.
    at ...NavBackStackEntry.getViewModelStore
    at androidx.lifecycle.viewmodel.compose.viewModel
    at ...ReaderScreen(ReaderScreen.kt:2275)
```

因此：占位转场用 `fadeIn/fadeOut(tween(700))`（`readerPlaceholderEnter/Exit`），
时长 ≥ 覆盖层退场弹簧的收敛时间（~420ms）；覆盖层再按 `entry.lifecycle` 是否
`≥ CREATED` 兜底停止组合，双保险。

## 9. 回归判定（真机 / 模拟器快速自查）

### 9.1 应用内取日志（无需 adb，推荐）

设置 → **诊断（返回跳动 / 折叠适配）**：

| 项 | 作用 |
|---|---|
| 记录诊断日志 | 开关（debug 构建默认开，release 默认关）。日志落盘到 `filesDir/diagnostics/return-trace.log`，超过 1.5MB 轮转为 `return-trace.1.log` |
| 在日志中打标记 | 复现"跳一下"的前后各点一次，日志里出现 `======== 标记 … ========` 分隔线，便于圈定区间 |
| 分享日志文件 | 导出到 `cacheDir/diagnostics/foldreader-log-<时间>.txt` 并走系统分享（微信/邮件/网盘均可）；失败会提示改用复制 |
| 复制日志到剪贴板 | 直接粘贴到聊天窗口 |
| 清空日志 | 删掉日志与崩溃转储 |

日志正文自带设备/屏幕/密度/尺寸类别/折叠形态（posture、铰链）与逐帧布局，
未捕获异常会先落盘到 `cacheDir/diagnostics/crash-*.txt` 再交给系统——崩溃现场不会丢。
