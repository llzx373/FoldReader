## 决策点（执行前需确认）

- **D1（A1 的前提）删书语义**：`reading_progress`/`bookmarks`/`annotations` 三表外键为 `NO_ACTION`，「不删本地数据」路径在 SQLite 层面走不通（删父行必违约），且孤儿数据按 bookId 锚定、书删后永远无法再访问。
  - **方案 A（推荐）**：删书时三张表**一律**随书删除；复选框语义收窄为「同时删除翻译、OCR、术语等派生产物」，文案相应改写。理由：孤儿行不可达、无恢复入口，「保留」没有实际价值。
  - 方案 B：保留「保留进度」语义 → 需数据库迁移重建三张表去掉外键（预发布期后已恢复向前兼容，迁移必须手写），并把书签总览等查询改为容忍孤儿。改动大、收益存疑。
- **D2（C13）双页「翻译本页」范围**：当前只翻跨页第一页。推荐改为**翻译整个跨页的两页**（与确认文案"范围：当前页"对齐）；备选是改文案为「当前左页/右页」。
- **D3（D9）dictzip 支持口径**：真实 StarDict `.dict.dz` 是多 gzip 成员串联。推荐**支持**（逐成员解压拼接）；备选为导入时检测多成员并明确报「暂不支持 dictzip」。

### A1 `fix(bookshelf): 删书流程事务化，消除外键违约崩溃`
- **问题**：`BookshelfRepositoryImpl.deleteBooks(deleteLocalData=false)`（`core/data/repository/BookshelfRepositoryImpl.kt:105-165`）跳过三张 `NO_ACTION` 子表的清理后 `bookDao.deleteByIds` 必抛 `SQLiteConstraintException`；且文件删除（封面/压平缓存/漫画缓存）发生在删行**之前**，崩溃后留下「行还在、文件没了」的半截状态。`BookshelfViewModel.deleteSelected`（`feature/bookshelf/BookshelfViewModel.kt:536-543`）无异常兜底。
- **修复**（按 D1 方案 A）：
  1. 三张 NO_ACTION 子表的删除移出 `if (deleteLocalData)`，**无条件**执行；
  2. 全部数据库删除包进一个 `@Transaction`（repository 层注入 `FoldReaderDatabase` 用 `withTransaction`，或在 DAO 加事务方法）；
  3. 文件系统删除挪到数据库删除**成功之后**；
  4. 复选框文案改为只描述派生产物（翻译/OCR/术语/统计之外已无独立的"本地数据"可保留——同步改 `BookshelfScreen.kt:919-952` 文案与 `docs/验收记录-书架与管理.md` 相关条目）；
  5. `BookshelfViewModel.deleteSelected` 加 `try/catch`，失败时 Snackbar 报错。
- **测试**：改写 `BookshelfRepositoryDeleteTest` 为 Robolectric + 真实 Room 内存库：造「有进度+书签+标注的书」，两种 flag 各跑一遍，断言不抛、行与文件状态一致。
- **边界**：不动 CASCADE 语义；`cleanedCandidates`/`sourceCopyCandidates` 的「删后反查再删文件」逻辑保留。

### A2 `fix(db): 书籍行更新改定点 UPDATE，消除 REPLACE 级联清空子表`
- **问题**：`BookDao.upsert`（`core/data/db/BookDao.kt:94-95`）的 `INSERT OR REPLACE` 对已有行是「删旧行+插新行」，触发所有 `CASCADE` 子表（chapters/book_prefs/offset_index/reading_sessions/person_appearances/translations/comic_page_translations/word_entries/chapter_summaries/book_outlines）整书清空；`NO_ACTION` 子表因同语句内父行重建不报错——`BookDao.kt:106-111` 注释的「REPLACE 会直接抛约束错误」论断是错的。活跃踩点：`FoldReaderApplication.kt:657-661` `onBookIndexed` 回填 `totalChars`（TXT 首开必触发；重洗/换编码重建索引时丢生词本、章节摘要、翻译台账）；`BackupCodec` 恢复命中已有书（A4 一并修）。
- **修复**：
  1. `BookDao` 新增 `@Query("UPDATE books SET totalChars = :totalChars WHERE id = :bookId")`；`FoldReaderApplication.onBookIndexed` 改用它；
  2. 全工程审计 `upsertBook`/`bookDao.upsert` 调用点：仅「确认是新书」的插入路径保留 `upsert`，凡可能命中已有行的一律改定点 UPDATE；
  3. 修正 `BookDao.kt:106-111` 与 `OffsetIndexEntity.kt:27` 的失实注释。
- **测试**：Room 内存库用例——插入书 + chapters + book_prefs + translation 台账，`upsert` 同 id（复现旧行为的反例断言可留 `@Ignore` 或直接删），再断言改用新 UPDATE 后子表全部存活。
- **边界**：不改表结构、不需要迁移（行为级修复）；`upsert` 方法本身保留给纯插入路径。

### A3 `fix(backup): 备份恢复补齐漫画页序、译文锚点与累计已读字符`

### B2 `fix(lock): 取消系统验证后不再软锁死`
- **问题**：`feature/lock/AppLock.kt:104-115` 的 `prompting` 只在 `onFailed` 复位，而 `:68-75` 对用户取消（`ERROR_USER_CANCELED`/`ERROR_NEGATIVE_BUTTON`）**不调** onFailed → 「解锁」按钮永久失效，只能杀进程。另：`SettingsScreen.kt:887-908` 关闭开关也走 `prompt`，设备锁屏被移除后 `canAuthenticate` 失败 → 开关关不掉。

### B3 `fix(ocr): 整页检测框不再回收调用方位图，det 输入位图补齐回收`
- **问题**：`core/ocr/android/OcrEngine.kt:246-252`——`Bitmap.createBitmap(src, 0, 0, w, h)` 裁剪区=整图时返回**源位图本身**，`:141` 的 `if (line !== crop) crop.recycle()` 会把传入的页位图回收，后续行裁剪全炸且漫画翻译后续渲染崩；`:124-125` 的 `detInput` 从不 recycle。

- **测试**：Robolectric 位图用例——构造整页框走一遍，断言传入位图 `isRecycled == false`。

### B4 `fix(ocr): 文本层页位图回收与缓存线程安全`

### B5 `fix(tts): 新朗读会话开始时清除旧睡眠定时`

### C7 `fix(comic): 跨页合并在翻译成功后才改写下一页气泡缓存`
- **问题**：`core/translate/ComicTranslateEngine.kt:252-267`（实际在 `feature/translate` 侧实现，执行时定位）在发起翻译**之前** `saveOcr` 重写页 N+1 气泡表；页 N 失败后续段在两页都不可见。且合并判定只查当前语言，另一语言已译时气泡表照样被改 → 对照错位。

- **测试**：`ComicTranslationE2ETest` 增用例——页 N 失败后页 N+1 渲染仍含续段。

### C8 `fix(ai): 取消流式请求时同步中断底层 HTTP 调用`
- **问题**：`core/ai/AiProvider.kt:8` 注释承诺「取消会中断底层 HTTP」，但三个 Provider 是阻塞 `execute()`+`readUtf8Line`，从不 `call.cancel()`——服务端断流时取消无效，请求占到 readTimeout。
- **修复**：阻塞调用包在可取消结构里（`suspendCancellableCoroutine`/`withContext` + `invokeOnCancellation { call.cancel() }`），三家 Provider 与 vision 路径同改。
- **测试**：mock 一个不发数据的流，取消收集端，断言 call 被 cancel、协程及时结束。

### C9 `fix(bookshelf): AI 批量补全首次确认后取消按钮生效`

- **测试**：VM 单测——确认路径起跑后 cancel，断言任务停止。

### C10 `fix(importer): 重洗改动检测改用全量内容哈希`
- **问题**：`feature/importer/RecleanBookUseCase.kt:75-82` 用 `ContentHasher` 的 3×8KB 采样哈希做「有无改动」判定；AI 校对的定点等长替换若不在采样窗口内 → 误判 no-op，修正静默不生效。
- **修复**：改动检测改用流式全量 SHA-256（一次性、本地文件，成本可接受）；`contentHash` 身份哈希保持采样不变（规格书决策）。

### C11 `fix(import): 导入/重洗取消不再被记为失败`
- **问题**：`ImportBookUseCase.kt:112,355`、`ComicImportUseCase.kt:73,110`、`PdfImportUseCase.kt:52`、`RecleanBookUseCase.kt:70` 的 `runCatching`/`catch(Throwable)` 吞 `CancellationException`——批量导入点取消时当前这本被记成虚假「失败」。

### C13 [决策点 D2] `fix(comic): 双页模式「翻译本页」覆盖整个跨页`

### C14 `fix(bookshelf): 顺序容器漫画预热完成后撤下「待解析」角标`

- **测试**：`BookEntity` 纯函数用例覆盖 zip/rar/目录三类的就绪与未就绪态。
